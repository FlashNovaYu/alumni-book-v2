# 同学相册投稿、照片移动与存储容量设计

日期：2026-07-28  
状态：已确认，待实施

## 目标

1. 修复私聊在真实浏览器流程中复现到的缺陷，并保持首条消息、已有会话和失败重试的一致体验。
2. 允许已登录的同学账号向唯一指定的“投稿相册”上传图片，每人当前最多保留五张投稿图片。
3. 让管理员能够将选择的照片批量移动到另一个相册。
4. 在管理后台展示自托管服务器容量和相册实际文件占用，便于控制本地上传目录的空间使用。

## 范围与非目标

- 投稿只允许投递到管理员指定的一个相册，图片上传成功后直接在该相册中展示。
- 不新增审核队列、评论、图片附件私聊或跨站点对象存储迁移。
- 当前限额是“仍保留在系统中的投稿照片”数；管理员删除该同学的投稿照片后，该同学重新获得一个名额。
- 容量面板的“服务器容量”指磁盘文件系统，不将内存（RAM）误报为图片存储容量。

## 备选方案与选择

| 方案 | 结论 | 原因 |
| --- | --- | --- |
| 允许同学选择任意相册 | 不采用 | 专题相册容易被误投，管理员治理成本高。 |
| 投稿先进入审核队列 | 不采用 | 当前需求未要求审核流程，会引入额外状态与后台操作。 |
| 唯一投稿相册、直接入册 | 采用 | 入口单一、实现最小，管理员仍可在后台整理移动。 |

## 数据模型

在 `albums` 表增加 `accepts_classmate_uploads INTEGER NOT NULL DEFAULT 0`。

- 管理后台保存相册设置时，启用该开关前先将其他相册的开关清零；数据库层以部分唯一索引确保最多一个相册可接收投稿。

在 `photos` 表增加：

- `submitted_by_slug TEXT`：同学投稿的登录标识；管理员上传的照片为 `NULL`。
- `upload_source TEXT NOT NULL DEFAULT 'admin'`：值为 `admin` 或 `classmate`。

建立 `(submitted_by_slug, upload_source)` 索引。限额查询只统计 `upload_source = 'classmate'` 且 `submitted_by_slug` 等于当前登录同学的仍存在照片记录。照片移动不改变这两个字段。

本地 SQLite 初始化 schema 与迁移测试数据库同步更新；Cloudflare D1 保持相同表结构。

## 同学投稿流程

1. 同学在个人资料编辑面板打开“向班级相册投稿”。未登录、首次密码尚未修改、未配置投稿相册时不可上传，并获得明确提示。
2. 客户端读取当前剩余额度；用户选择图片后，逐张限制为剩余额度以内。
3. 每张图在浏览器内转换为 WebP：最长边 1920px、质量 0.82；并生成 640px 和 1280px 展示变体，减少上传和持久化空间。
4. `POST /api/classmate/album-photos` 使用 `X-Classmate-Token` 鉴权。服务端只从数据库读取指定投稿相册，不接受客户端传入的目标相册 ID。
5. 服务端验证会话、首次密码状态、图片 MIME/内容/体积、当前照片数量与文件变体；到达五张时拒绝并返回剩余数量。
6. 上传对象完成后，插入带投稿人归属的照片记录；插入失败则删除本次原图和全部变体。成功后返回新照片及剩余额度。

这样即使客户端并发提交，也由服务端最终的限额检查保证上限。实现时使用 SQLite/D1 可用的原子写入或可重试保护，避免并发超过五张。

## 后台相册管理

### 投稿相册设置

在创建/编辑相册表单增加“接收同学投稿”开关，配以“同时只能指定一个相册”的提示。相册列表展示投稿标记。

### 批量移动照片

“管理相册”弹窗的照片列表新增多选；选中至少一张后可选择目标相册并确认移动。

`POST /api/photos/move` 接收 `photoIds` 与 `targetAlbumId`，要求 `content.manage` 权限，验证：

- 数组非空、无重复且所有照片存在；
- 目标相册存在；
- 不允许把照片移动到其当前相册；
- 目标相册中按所选照片原有排序顺序追加新的 `sort_order`。

数据库更新与审计日志在同一批次提交。对象键、变体元数据、说明、投稿归属不变，因此不复制、不重新压缩、也不增加额外存储。前端成功后刷新源/目标相册列表。

## 存储容量接口与面板

新增管理接口 `GET /api/albums/storage`，要求 `content.manage` 权限。

自托管 Node 运行时返回：

- `filesystem.totalBytes`、`usedBytes`、`availableBytes`：通过上传目录所在文件系统的 `statfs` 计算；
- `uploads.totalBytes`：上传根目录全部文件（不含 metadata sidecar）的占用；
- `albums.totalBytes`：当前 `photos` 表引用的原图和变体对象总和；
- `environment: 'self-hosted'`。

Cloudflare Worker 运行时返回 `environment: 'cloudflare'` 和 `available: false`，后台显示为“不提供服务器磁盘统计”。不得以 R2 列表或空值伪造服务器总容量。

管理后台相册页顶部显示容量卡片：服务器总容量、已使用、可用、相册占用；字节数统一格式化为 B/KB/MB/GB，并在统计不可用时显示原因。

## 私聊修复与验证

先通过 Playwright 正确执行 `chat-rework-flow.spec.ts` 和 `post-office-flow.spec.ts`。此前将 Playwright spec 误交由 Vitest 会报测试框架 hook 错误，不能作为产品失败结论。

若浏览器回归发现缺陷，修复范围限定在私聊 API 客户端/`useInbox`/对应路由，并补充或更新以下覆盖：

1. 新建会话的首条消息立即可见并被服务端结果替换；
2. 已有会话发送后消息与会话列表更新时间一致；
3. 失败消息可以用同一幂等 nonce 重试。

## 安全与一致性约束

- 同学自助接口只信任服务端从会话提取的 slug，不能接受客户端指定的投稿人或目标相册。
- 管理员移动接口延续现有 JWT、密码已修改与 `content.manage` 权限检查，并写入审计日志。
- 所有上传流程遵循“对象上传失败不写数据库；数据库失败补偿删除新对象”。
- 本地文件路径、数据库、发布环境文件和既有未提交的用户图片均不清理、不输出、不纳入本次提交。

## 验收标准

1. 未登录、首次改密前、未配置投稿相册、格式/体积不合法、超过五张、伪造相册 ID 等请求均被正确拒绝。
2. 同学上传的图片经过压缩和变体生成，真实图片可经同源 `/api/files/` 访问；删除后额度恢复。
3. 管理员可选择多张照片并移动到另一相册，排序、图片 URL、说明和投稿归属保持正确。
4. 自托管容量接口与临时目录中的已知字节数一致；Cloudflare 返回不可用状态。
5. 私聊浏览器回归通过，受影响 Worker、Node、admin、site 测试与类型检查通过。
6. 阿里云发布后，公开 `release.json`、API/static SHA、health/readiness、受影响业务 smoke 均证明为同一新发布版本。
